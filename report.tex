\textbf{Abstract.}\enspace
This report audits a mobile-money transaction ledger for the credit-risk
function, with the explicit goal of establishing whether the resulting model
can be \emph{trusted} in production---not merely how accurate it looks offline.
We identify and remediate \textbf{ten data-quality defects}, document the
lineage and fairness posture of \textbf{twenty-eight engineered features}
across five behavioural families, and diagnose \textbf{two planted leakage
sources} that inflate offline ROC-AUC from a genuine \textbf{0.6274} to an
artefactual \textbf{1.0000} (+0.3747 artificial inflation). All preprocessing
and modelling is encapsulated in a single \texttt{scikit-learn Pipeline},
evaluated with customer-grouped cross-validation and persisted with
\texttt{joblib} for direct deployment. The leakage-free ROC-AUC of
\textbf{0.6274\,$\pm$\,0.0038}---not 1.0000---is the only figure recommended
for business planning.
\end{mdframed}

\section{Leakage Assessment Memo}
\label{sec:leakage}

Two fields are written to the ledger only \emph{after} a transaction is
reviewed, reversed, or settled. Both were identified as planted leakage
sources and permanently removed prior to modelling.

\subsection*{Source 1 --- \texttt{manual\_review\_score} (Target Leakage)}

A numeric score in $[0,1]$ populated by fraud analysts during post-event
review---after \texttt{is\_fraud} is already known. The field originates from
the fraud-operations system, not the transaction-processing system, and does
not exist at live scoring time.

\textbf{Evidence.} Pearson $|r|{=}0.981$ with \texttt{is\_fraud}.

\textbf{Leakage type (\S2.7.2).} Target leakage / lookahead: a variable
causally downstream of the target is included as a predictor.

\textbf{Governance.} Feature-availability gate excluding any candidate
whose \texttt{availability\_timestamp} exceeds \texttt{txn\_time}; dual
sign-off required for features with $|r|{>}0.3$ against the target.

\subsection*{Source 2 --- \texttt{settlement\_status} (Temporal Leakage)}

A zero-missingness categorical field (\texttt{settled}, \texttt{reversed},
\texttt{held}, \texttt{pending}) that resolves asynchronously, hours to weeks
after the transaction. The training set back-filled future state into an
apparently contemporaneous column at data-assembly time.

\textbf{Evidence.} \texttt{reversed} transactions carry a fraud rate of
1.000 ($n{=}9{,}903$) versus 0.004 for \texttt{settled}
($n{=}154{,}760$); reversal is a consequence of fraud, not a signal.

\textbf{Leakage type (\S2.7.2).} Temporal leakage / train--inference
skew: post-event state is joined without an availability constraint.

\textbf{Governance.} Flag post-event fields
\texttt{is\_available\_at\_scoring: false} in the registry; supplement CV
with a temporal holdout (train months 1--10, evaluate months 11--12).

\section{Reproducible Machine Learning Pipeline}
\label{sec:pipeline}

\subsection*{Design}

All preprocessing (imputation, power transform, scaling, one-hot encoding)
is fitted exclusively within each CV training fold via a single
\texttt{scikit-learn Pipeline}. No transformer sees validation data during
fitting; no step is performed outside the pipeline object.

\begin{lstlisting}[caption={End-to-end pipeline.}]
def build_pipeline(num_cols, cat_cols):
    num_pipe = Pipeline([
        ('impute', SimpleImputer(strategy='median',
                                 add_indicator=True)),
        ('power',  PowerTransformer(method='yeo-johnson')),
        ('scale',  RobustScaler())])
    cat_pipe = Pipeline([
        ('impute', SimpleImputer(strategy='constant',
                                 fill_value='UNK')),
        ('onehot', OneHotEncoder(
            handle_unknown='infrequent_if_exist',
            min_frequency=50))])
    prep = ColumnTransformer([
        ('num', num_pipe, num_cols),
        ('cat', cat_pipe, cat_cols)])
    return Pipeline([('prep', prep),
        ('clf', LogisticRegression(
            max_iter=2000, C=1.0, solver='lbfgs'))])
\end{lstlisting}

\subsection*{Group-Aware Cross-Validation}

\texttt{GroupKFold(n\_splits=5)} grouped by canonical
\texttt{customer\_id} keeps all transactions for each customer in
one fold, preventing customer-behaviour leakage across folds.

\subsection*{Persistence \& Verification}

The pipeline is refit on all 180,000 records and saved with
\texttt{joblib}. Reload is verified by asserting byte-identical
\texttt{predict\_proba} output on a held-out sample.

\begin{lstlisting}[caption={Persistence and verification.}]
import joblib, numpy as np
joblib.dump(final_pipeline, "final_pipeline.joblib")
reloaded = joblib.load("final_pipeline.joblib")
assert np.allclose(
    final_pipeline.predict_proba(X_sample)[:, 1],
    reloaded.predict_proba(X_sample)[:, 1])
\end{lstlisting}

The marker may load the artefact and call
\texttt{pipeline.predict\_proba(X\_new)[:,1]} directly---no manual
preprocessing is required.

\textbf{Environment:} Python 3.12.3 \textbullet\ pandas 3.0.2
\textbullet\ scikit-learn 1.8.0 \textbullet\ joblib 1.5.3.

\textbf{Model choice.} Logistic regression is chosen deliberately:
coefficients remain interpretable for adverse-action reasoning and
Model Risk review. Gradient-boosted trees (XGBoost, LightGBM) are
the natural next iteration under the same grouped-CV protocol.
